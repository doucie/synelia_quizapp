# Améliorations UX/UI et fonctionnalités — 18 avril 2026

> **Objectif** : Améliorer l'ergonomie, la cohérence visuelle et les fonctionnalités du dashboard.
>
> **Contexte** :
> - Backend : Spring Boot 3.5.6, Java 21, Hibernate 6.6.x, MySQL 8.0.43, Flyway (V1_015)
> - Frontend : Angular 20.2.0, Standalone components, Signals, SCSS
> - Sidebar : 18 `menuItems` dans `filteredMenuItems()`, 34 `entitiesList` items
> - Dashboard pages existantes : overview, entities, merise, profile, settings, users, campaigns, candidates (applications), decisions, interviews, evaluations, pipeline-templates, system-role-permissions, business-groups, user-permissions
> - Pages dashboard **manquantes** : departments, specialities, questions, answers (les `menuItems` pointent vers des routes inexistantes)
> - Entities pages : 36 composants dans `entities/solo/`
> - Pattern entité shared : `entities-solo.scss` (stats-bar, pagination-container, data-table, action-btn)
> - Styles globaux : `styles.scss` + `styles/core/` (colors.css, surfaces.css, variables.css)
>
> **Conventions** :
> - Pas de couleurs en dur — utiliser variables CSS
> - Responsive obligatoire
> - Pattern signals/computed Angular
> - localStorage pour préférences utilisateur
> - SVG inline pour les icônes

---

## Règles à respecter

- Séparer optimalement frontend (`/quizapp_front`) et backend (`/quizapp`)
- S'assurer que le code soit optimisé
- Créer une migration MySQL si nécessaire
- Mettre la checklist de ce fichier à chaque itération
- Interdiction d'utiliser des couleurs autres que celles qui sont dans les variables existantes
- Interdiction d'utiliser des couleurs en dur, utiliser les variables de couleur présentes
- Les pages doivent être responsives
- Regarder l'existant avant de créer quelque chose : si quelque chose de similaire existe déjà, faire la même chose
  - Backend : les endpoints se répètent (même pattern pour chaque controller)
  - Frontend : réutiliser les pages, boutons, styles existants — pattern `EntityCrudBase` quand c'est néccéssaire sinon créer de nouveaux styles/composants/designs modernes allant avec le design actuel
- Convention update partiel : `""` → ignorer, `null` → mettre à null, autre → mettre à jour
- Convention API : tout en POST, jamais de GET/PUT/DELETE
- Frontend : envoyer `null` au lieu de `""` quand un champ est vide
