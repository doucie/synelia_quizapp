# Conformité des pages entités avec la base de données

> **Objectif** : Mettre en conformité les pages `/dashboard/entities/` et le dropdown
> `entitiesList` avec l'état réel de la base de données après les migrations V1_001 → V1_014.
>
> **Contexte** :
> - Backend : Spring Boot 3.5.6, Java 21, Hibernate 6.6.x, MySQL 8.0.43, Flyway
> - Frontend : Angular 20.2.0, Standalone components, Signals/Computed, SCSS
> - 36 tables en BDD (35 actives + 1 droppée `campaign_questions`)
> - 39 controllers backend
> - 24 répertoires de composants entité (+ `shared/`)
> - 18 entrées dans le dropdown `entitiesList`
> - 6 entités avec routes/composants mais PAS dans le dropdown
> - 12 tables avec controllers mais SANS page entité frontend
>
> **Résumé des écarts** :
> - 2 entités à supprimer/déprécier du dropdown (tables renommées/migrées)
> - 6 entités à ajouter au dropdown (composants existants mais non listés)
> - 9 entités à créer (tables + controllers existent, pas de page entité)
> - 3 tables sans controller CRUD dédié → à créer (email_verification_tokens, business_group_permission, user_business_group)
> - 3 pages entité supplémentaires à créer pour ces nouvelles APIs
> - 10 entités avec des colonnes manquantes dans le tableau
> - 1 renommage backend en attente (interview_crud → interview_participant)
>
> ---
>
> **Convention API** : tout en POST (sécurité : pas de paramètres dans l'URL/logs)
> **Convention update partiel** : `""` → ignorer, `null` → mettre à null, autre → mettre à jour
> **Endpoints standard** : `/create`, `/update`, `/delete`, `/getByCriteria`, `/getAllByCriteria`, `/updateAll`, `/updateDeleted`
> **Pattern entity page** : hériter `EntityCrudBase`, configurer `entityTypeApi`, `columns`, laisser le detail-panel auto-généré
> **Pas de couleurs en dur** — utiliser les variables CSS existantes
> **Responsive** obligatoire
> **Réutiliser l'existant** : regarder les composants entité existants avant de créer
