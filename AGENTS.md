# AGENTS.md — Contexte projet pour les sessions

Projet de fin d'études (ENSIT 2026, entreprise SYNELIA) : plateforme web de **recrutement via quiz**,
avec processus complet (campagnes, candidatures, quiz, entretiens, évaluations, décisions).
Vue d'ensemble rapide : `README.md` racine.

## Blocs principaux

| Dossier | Rôle |
|---|---|
| `quizapp/` | Backend **Java 21 / Spring Boot 3.5** (WAR). Package `tech.synelia.quizapp`. JPA/MySQL, migrations Flyway, API **tout en POST** (`POST /entity/action`, format `{user, datas[]}`), code généré Telosys (`TelosysTools/`). |
| `quizapp_front/` | Frontend **Angular 20** (SCSS, BEM, variables CSS `:root`). Parcours candidat + dashboard. Routes : `src/app/app.routes.ts`. |

| `cartographie-fonctionnelle-front/` | Cartographie métier route-first, base de données cible, audits, évolutions fonctionnelles. |

## figures_flow (contexte de travail le plus actif)

- Démarrer : `cd z_mémoire/figures_flow && npm run dev`. Build : `npx vite build`. Typecheck : `npx tsc --noEmit`.
- Projet **indépendant** du front Angular. Docs : `README.md` dédié + méthode Merise dans `plans/rules/regles_mcd.md`.
- Persistance **localStorage** : positions `figures_flow:diagram:<id>`, côtés de cardinalité `figures_flow:edge_sides:<id>`, et **overlay debug** `figures_flow:debug_edges` (bouton `DEBUG` en haut-droite → ancrage déclaré→résolu, taille de groupe, offset px). L'overlay est porté par `RelationshipEdge`, `TraitementEdge` **et `OrgBusEdge`**, et il passe obligatoirement par `EdgeLabelRenderer` : `BaseEdge` rend un `<path>` dans le `<svg>` de React Flow, donc un `<div>` posé à côté serait créé dans le namespace SVG — un élément inconnu, sans rendu. Pour l'organigramme il affiche `runY` / `targetY` / `dY` et la hauteur **mesurée** sur le plancher, ce qui est le seul moyen de savoir si une boîte dépasse son `minHeight`.
- Plans par convention : `plans/implementations/YYYYMMDD_<sujet>.md`, avec checkboxes `[ ]`/`[x]`.
- Export SVG (figure + bloc ⤓) : deux règles — **l'invariant de placement** (un raster est dimensionné *et* positionné d'après la boîte de l'élément réellement rasterisé ; contrat `[data-export-root]` pour les nœuds composites comme `mct-syncop`, sinon `dx`/`dy` mesurés par `captureNodePadded`) et **bordure des cartes repeinte au raster** — `plans/rules/regles_export_svg.md` (préalables : polices auto-hébergées dans `src/assets/fonts/`, variables `--mct-*` recopiées sur le wrapper de capture).

Conséquence assumée : `OrgBusEdge` **n'applique ni `edgePathOffset` ni le décalage de `TraitementEdge`** — ne pas les lui ajouter, un organigramme veut une barre, pas une gerbe.
- **`trunkFraction` fait partir la course horizontale le long de la descente** (0 = bord de la source, 1 = barre, défaut). Le PMO s'accroche ainsi au **milieu du tronc** du SG (`trunkFraction: 0.5`, `busGap` aligné sur celui des directions, `targetHandle: 'left'`, `busRadius: 0`) au lieu de partir de la boîte. `roundedPolyline` (OrgBusEdge.tsx:17) ne arrondit que les points **intérieurs** de la polyligne : l'arrivée n'a donc un angle que si `targetY ≠ runY`. `PMO_CX` est calé sur le **gouttier entre les 4ᵉ et 5ᵉ directions** (`colX(3) + DIR_W/2 + (COL_PITCH - DIR_W)/2`), pas sur un pourcentage : l'original était à 73 %, il a été poussé à droite, et une référence de la figure ne se désynchronise pas quand `COL_PITCH` bouge.
- **La formule qui gouverne ce raccord : `dY = (NOM.gov − h_sg) + (h_pmo − NOM.pmo) / 2`.** Les deux termes doivent être nuls, pour deux raisons distinctes : `NOM.gov` cale la course (elle part du bas **réel** du SG), `NOM.pmo` cale l'arrivée (elle vise le centre **réel** du PMO). Un seul des deux suffit à casser l'arrivée, et le symptôme — un décrochement à la face du PMO — ne désigne pas la cause : seul le tableau de `OrgBusEdge` la trouve. Le dégagement sous le PMO n'est pas un choix mais une **conséquence**, `bar / 2 − NOM.pmo / 2`, Toute variante du PMO doit revalider ce triptyque.
- **`NOM` est un relevé, pas un calcul.** Les planchers se **mesurent** (tableau journalisé par `OrgBusEdge`, bouton DEBUG) : le calcul « pire cas de la rangée » s'est trompé sur 2 boîtes sur 23 — **Ces valeurs sont périmées** : le relevé du 2026-10-04 donne `gov` 154, `pmo` 156, `dir` 204, et les 23 boîtes mesurent *exactement* leur plancher. Les deux dépassements venaient d'un **double encodage CP1252** du fichier (commit `0efbba4`) : `é` y occupait deux caractères, donc les intitulés passaient sur une ligne de plus. Ne pas réestimer à la main, ne jamais fixer `height`.
- **Les hauteurs ne se lisent qu'après chargement de la fonte** (`font-display: swap`) : un relevé pris pendant le fallback donne 3 px de trop sur le SG et un `runY` faux. Le tableau journalise deux fois au démarrage — seule la dernière passe compte.
- **Les colonnes de services n'ont que 22 px d'entraxe** (`SVC_PITCH = SVC_H[i] + V.svc`) : un plancher dépassé par une direction fait chevaucher ses propres services. C'est la seule raison pour laquelle `d2` avait été abrégée en `Prod. & Expérience Client` — à 450 px de large elle tient en entier, donc `Production & Expérience Client` est revenu. Corollaire : **un plancher est une marge, pas une mesure** — mais ici le relevé est exact et les 20 px de chrome suffisent (cf. `SVC_H`), donc aucune marge n'a été ajoutée.
- **Les services sont empilés** (entraxe de 255 px, trois boîtes de 450 px). Il n'y a **plus aucune arête** entre une direction et ses services, donc plus de trait vertical à dessiner : `V.dirToSvc` (40) ne sert plus qu'à laisser respirer la rangée.
- `org-box` est une `Variant` dispatchée depuis `EntityNode` (comme `mpd-sql` → `SqlScriptBlock`) ; l'arête est `type: 'orgBus'`. `ORG_VERTICAL_VARIANTS` et `VERTICAL_SOURCE/TARGET_HANDLES` dans `edgeAnchors.ts` sont partagés avec le MCT : l'ordre des `<Handle>` de `OrgNode` doit rester aligné sur `handleIdsOf`.
- **Les handles d'`OrgNode` sont posés en `style` inline** (`HANDLE_STYLE`, taille nulle) : `@xyflow/react` impose `width/height: 6px` dans une feuille **non mise en couche**, qui bat Tailwind. Sans ce contournement chaque ancre est décalée de 3 px vers l'intérieur de la boîte et une pastille est visible à l'impression. `ProcessNode` a le même défaut, non corrigé — hors périmètre.
- **La page paysage passe par `#landscape-figure`** (`theme.typ`), importé dans `body.typ`. Deux contraintes non négociables : largeur d'image **explicite** (`width: 25.3cm`, jamais `100%` — un pourcentage dans une boîte auto est circulaire) et `placement: none` (`header: none` sur cette page, donc une figure flottée n'aurait nulle part où aller).
