    Introduction

    Ce document constitue le Cahier des Charges Fonctionnel de l'application SyneliaQuizApp, une solution web dédiée à la gestion du processus de recrutement avec évaluation technique automatisée.

    Il a pour objectif de formaliser les besoins exprimés par l'entreprise SYNELIA et de définir les spécifications fonctionnelles et techniques de la solution à développer.

    Objectif du document
    Ce cahier des charges sert de référence commune entre les parties prenantes du projet. Il définit le périmètre, les fonctionnalités attendues et les contraintes à respecter.

    Structure du document

    Le présent document est organisé comme suit :

    • Partie I - Présentation Générale : Contexte du projet, objectifs stratégiques et opérationnels, périmètre fonctionnel
    • Partie II - Acteurs et Cas d'Utilisation : Identification des acteurs (internes et externes), parcours utilisateurs, priorisation MoSCoW
    • Partie III - Spécifications Fonctionnelles : Exigences détaillées par module (11 modules), exigences non-fonctionnelles
    • Partie IV - Architecture et Sécurité : Stack technologique, architecture 3-tiers, mesures de sécurité, conformité RGPD
    • Annexes : Glossaire, diagrammes UML, maquettes d'écran
    ⚡ Point clé
    Ce cahier des charges met en avant la fonctionnalité de sauvegarde automatique des réponses du quiz, permettant aux candidats de reprendre leur évaluation en cas d'interruption.
    I

    Présentation Générale

    Cette partie présente le contexte du projet, les objectifs poursuivis et le périmètre fonctionnel de l'application.

    1 Contexte du Projet

    1.1 Présentation de l'entreprise

    SYNELIA est une entreprise spécialisée dans les services informatiques et le conseil en technologies. En pleine croissance, l'entreprise fait face à des besoins de recrutement importants pour renforcer ses équipes techniques et accompagner son développement.

    Le département des Ressources Humaines gère actuellement plusieurs dizaines de recrutements par an, avec des profils variés allant des développeurs juniors aux experts seniors, en passant par les chefs de projet et consultants.

    1.2 Problématique

    Le processus de recrutement actuel chez SYNELIA présente plusieurs difficultés majeures :

    Processus manuel et chronophage

    • Les candidatures arrivent par différents canaux (email, site web, LinkedIn, cabinets)
    • Le tri des CV se fait manuellement, sans critères standardisés
    • La planification des entretiens nécessite de nombreux échanges emails
    • Le suivi des candidatures est effectué sur des fichiers Excel dispersés

    Absence de centralisation

    • Pas de base de données unique des candidats
    • Informations éparpillées entre plusieurs outils
    • Difficulté à retrouver l'historique d'un candidat
    • Pas de vision globale sur les campagnes en cours

    Évaluations non standardisées

    • Chaque recruteur évalue selon ses propres critères
    • Pas de grille d'évaluation commune
    • Difficile de comparer objectivement les candidats
    • Les compétences techniques ne sont pas vérifiées de manière uniforme

    Manque de traçabilité et expérience candidat dégradée

    • Impossible de savoir d'où viennent les meilleurs candidats
    • Pas de métriques sur l'efficacité des sources de recrutement
    • Délais de réponse trop longs pour les candidats
    • Image de l'entreprise impactée

    1.3 Besoin de digitalisation

    Face à ces constats, SYNELIA souhaite se doter d'un outil moderne permettant de :

    1. Centraliser toutes les candidatures dans une plateforme unique
    2. Automatiser les tâches répétitives (emails, évaluations techniques)
    3. Standardiser le processus d'évaluation des candidats
    4. Collaborer efficacement entre les différents acteurs du recrutement
    5. Suivre l'ensemble des candidatures en temps réel
    6. Mesurer la performance du processus de recrutement

    2 Objectifs du Projet

    2.1 Objectifs stratégiques

    Objectif Description
    Digitaliser le processus Remplacer les processus manuels par une plateforme web centralisée permettant de gérer l'intégralité du cycle de recrutement
    Automatiser l'évaluation technique Intégrer un système de quiz technique permettant de pré-filtrer les candidats de manière objective avant les entretiens
    Faciliter la collaboration Permettre à plusieurs recruteurs d'évaluer simultanément les candidats et de partager leurs avis en temps réel
    Améliorer l'image employeur Offrir aux candidats une expérience de candidature moderne et fluide

    2.2 Objectifs opérationnels

    Objectif Cible
    Réduire le temps de traitement d'une candidature -50%
    Diminuer le nombre d'emails échangés -70%
    Augmenter le taux de réponse aux candidats 100% dans les 48h
    Standardiser les évaluations techniques 100% des candidats passent le quiz
    Centraliser les données candidats Base unique accessible à tous

    2.3 Indicateurs de succès (KPIs)

    KPIs quantitatifs :
    • Nombre de candidatures traitées par mois
    • Temps moyen de traitement d'une candidature
    • Taux de conversion candidature → entretien → embauche
    • Score moyen des candidats aux quiz techniques
    • Nombre d'évaluations collaboratives réalisées
    KPIs qualitatifs :
    • Satisfaction des recruteurs (enquête interne)
    • Satisfaction des candidats (enquête post-candidature)
    • Qualité des embauches (évaluation à 6 mois)

    • Les candidats possèdent une adresse email valide
    • L'entreprise dispose d'un serveur de messagerie fonctionnel

    Administrateur

    RE

    Recruteur

    Chargé de recrutement opérationnel. Gère les campagnes, planifie les entretiens, évalue les candidats et prend des décisions sur les candidatures.

    5 Cas d'Utilisation

    Workflow global du processus de recrutement
    Le système implémente un workflow complet articulé en 6 phases séquentielles avec transitions d'état automatisées :
    1. Soumission → Le candidat postule via un lien traçable (SourceToken). Statut : PENDING
    2. Vérification → Validation de l'email + passage du quiz technique. Statut : VERIFIED
    3. Tri & scoring → Score automatique du quiz + consultation du CV par le recruteur. Filtrage et recherche multicritère. Statut : REVIEWED
    4. Entretien → Planification et conduite des entretiens (présentiel/visio). Statut : INTERVIEW_SCHEDULED
    5. Évaluation collaborative → Notation partagée sur 100 avec synchronisation temps réel (WebSocket). Statut : EVALUATED
    6. Décision → Acceptation ou refus avec notification automatique au candidat. Statut : ACCEPTED / REJECTED
    Chaque transition déclenche une notification email et/ou in-app. Le tableau de bord fournit des métriques en temps réel sur l'avancement du pipeline.

    5.1 Parcours Candidat

    Le parcours du candidat se déroule en 5 étapes principales :

    Étape 1 : Découverte de l'offre
    Le candidat reçoit un lien de partage (via email, LinkedIn, site web). Le lien contient un token de source permettant de tracer l'origine de la candidature.
    Étape 2 : Soumission de la candidature
    Remplissage du formulaire avec : informations personnelles (nom, prénom, email, téléphone, date de naissance), upload du CV (PDF, DOC, DOCX), lettre de motivation optionnelle, et acceptation du consentement RGPD.
    Étape 3 : Vérification de l'email
    Réception d'un email de confirmation avec un lien de vérification. Le clic sur le lien valide l'adresse email et débloque l'accès au quiz technique.
    Étape 4 : Passage du quiz technique
    Accès au quiz via un lien sécurisé (token unique). Le candidat lit les instructions, répond aux questions (QCM), avec une sauvegarde automatique des réponses à chaque question. Un mode anti-triche peut être activé (blocage copier-coller, détection changement d'onglet). Le score est calculé automatiquement à la soumission.
    Étape 5 : Suivi de la candidature
    Accès à une page de suivi avec code personnel, visualisation du statut actuel, historique des étapes franchies, et réception d'emails à chaque changement de statut.

    5.2 Parcours Recruteur

    Le recruteur suit ce workflow complet :

    1. Création de campagne : Définition du poste, de la spécialité requise, configuration du quiz (nombre de questions, mode chronométré, mode anti-triche)
    2. Génération des tokens de partage : Création de liens traçables pour différentes sources (LinkedIn, site web, cabinets, etc.)
    3. Réception des candidatures : Notifications en temps réel, consultation de la liste avec filtres, tri et recherche multicritère
    4. Analyse des profils : Visualisation du CV, de la lettre de motivation, du score au quiz et du journal anti-triche
    5. Planification des entretiens : Sélection des candidats, création d'entretiens (date, type, lieu/lien visio), visualisation via le calendrier intégré (vues année/mois/jour)
    6. Évaluation collaborative : Interface partagée avec notation sur 100, commentaires, et synchronisation en temps réel
    7. Prise de décision : Acceptation ou refus, déclenchement des notifications automatiques au candidat

    5.3 Parcours Super Administrateur

    Le super administrateur est responsable de la configuration technique du système :

    1. Gestion des données de référence : Création et organisation des départements de l'entreprise, définition des spécialités par département
    2. Alimentation de la banque de questions : Création des questions techniques par spécialité, définition du temps alloué par question, création des réponses possibles et marquage des bonnes réponses
    3. Gestion des utilisateurs système : Création de tous les types de comptes (super admin, admin, recruteur), attribution et modification des rôles, suppression définitive des comptes
    4. Configuration avancée : Accès à toutes les fonctionnalités du système, supervision globale de l'activité

    5.4 Parcours Administrateur

    L'administrateur gère les opérations RH quotidiennes :

    1. Gestion des recruteurs : Création des comptes recruteurs, attribution des rôles (admin ou recruiter uniquement), activation/désactivation des comptes
    2. Supervision des campagnes : Vue globale sur toutes les campagnes de recrutement, accès aux statistiques consolidées
    3. Gestion des candidatures : Consultation de toutes les candidatures, possibilité d'annuler des décisions prises par les recruteurs
    4. Consultation du tableau de bord : Visualisation des indicateurs clés, suivi des activités en cours

    6.6 Module Quiz Technique

    ⚡ Fonctionnalité clé : Sauvegarde automatique
    Le système enregistre automatiquement chaque réponse sélectionnée par le candidat. Cette protection contre la perte de données permet au candidat de reprendre le quiz à la dernière question sauvegardée en cas de déconnexion ou fermeture du navigateur.
    ID Exigence Priorité
    QUIZ-01 Le quiz doit afficher les questions une par une MUST
    QUIZ-02 Le système doit sauvegarder les réponses automatiquement à chaque sélection MUST
    QUIZ-03 Le candidat doit pouvoir reprendre le quiz après déconnexion MUST
    QUIZ-04 Un chronomètre doit s'afficher si le quiz est chronométré SHOULD
    QUIZ-05 Le score doit être calculé automatiquement à la soumission MUST
    QUIZ-06 Le candidat doit pouvoir naviguer entre les questions SHOULD
    QUIZ-07 Une barre de progression doit indiquer l'avancement SHOULD
    QUIZ-08 Les états du quiz sont : PENDING → IN_PROGRESS → COMPLETED MUST
    QUIZ-09 Le mode anti-triche doit bloquer le clic droit, la sélection de texte et les raccourcis copier/coller pendant le quiz SHOULD
    QUIZ-10 Le changement d'onglet ou de fenêtre doit être détecté et journalisé (nombre de tentatives enregistré) SHOULD
    QUIZ-11 Au-delà d'un seuil configurable de changements d'onglet, un avertissement doit être affiché au candidat et le recruteur doit être notifié COULD
    🛡️ Mode Anti-Triche
    Pour garantir l'intégrité des évaluations techniques, l'application intègre un mode anti-triche activable par campagne. Ce mode :
    • Désactive le clic droit et le menu contextuel sur l'interface du quiz
    • Bloque la sélection de texte et les raccourcis clavier (Ctrl+C, Ctrl+V, Ctrl+A)
    • Détecte les changements d'onglet via l'API Page Visibility et enregistre chaque occurrence
    • Affiche un avertissement au candidat après un nombre configurable de tentatives de sortie
    • Enregistre un journal des incidents consultable par le recruteur dans le détail de la candidature

    7.4 Maintenabilité

    • Architecture modulaire : Séparation claire des couches (Controller, Service, Repository)
    • Code documenté : JavaDoc pour les classes publiques, commentaires pour la logique complexe
    • Conventions de nommage : CamelCase pour Java, kebab-case pour Angular
    • Tests unitaires : Couverture minimale de 60% pour les services métier
    • Logs structurés : Utilisation de SLF4J avec niveaux INFO, WARN, ERROR

    7.5 Scalabilité et Évolutivité

    L'architecture de l'application est conçue pour supporter une montée en charge progressive :

    • Scalabilité horizontale : L'application Spring Boot est stateless (session externalisable), permettant le déploiement de plusieurs instances derrière un load balancer
    • Base de données : MySQL supporte le read-replica pour distribuer la charge en lecture. Les index sont optimisés pour les requêtes fréquentes (recherche candidats, filtrage par statut)
    • Pagination systématique : Toutes les API de liste utilisent la pagination (paramètres page/size) pour limiter la charge mémoire
    • WebSocket scalable : L'utilisation de STOMP permet de migrer vers un broker externe (RabbitMQ, Redis Pub/Sub) en cas de montée en charge
    • Upload fichiers : Stockage sur système de fichiers avec possibilité de migration vers un stockage objet (S3, MinIO) pour la scalabilité

    Prévisions de capacité : L'application est dimensionnée pour gérer simultanément 50 campagnes actives, 500 candidatures par mois, et 20 utilisateurs internes connectés.

    Cette partie décrit l'architecture technique et les mesures de sécurité de l'application.

    8 Architecture Technique

    8.1 Architecture Globale

    L'application adopte une architecture 3-tiers classique :

    Couche Présentation (Frontend)
    Application Angular (SPA) communiquant avec le backend via API REST. Gère l'interface utilisateur, la navigation et l'état local.
    Couche Métier (Backend)
    Application Spring Boot exposant des services REST. Implémente la logique métier, les règles de gestion et l'orchestration des traitements.
    Couche Données
    Base de données MySQL stockant l'ensemble des données persistantes. Accès via Spring Data JPA avec mapping Hibernate.

    Glossaire

    Termes Métier

    Anti-Triche (Mode)
    Ensemble de mécanismes de sécurité appliqués pendant le passage du quiz : blocage du clic droit, désactivation du copier-coller, détection des changements d'onglet via l'API Page Visibility.
    Calendrier Intégré
    Composant visuel permettant de planifier et visualiser les entretiens sur trois niveaux de zoom : vue année, vue mois et vue jour.
    Campagne
    Offre de recrutement pour un poste spécifique, avec ses propres paramètres de quiz, dates de validité et critères de sélection.
    Candidature (Application)
    Dossier soumis par un candidat pour un poste, comprenant ses informations personnelles, son CV et éventuellement une lettre de motivation.
    Entretien (Interview)
    Rencontre planifiée entre le candidat et les recruteurs, pouvant être en présentiel ou en visioconférence.
    Évaluation
    Notation et commentaires attribués par les recruteurs à un candidat suite à un entretien.
    QEEL
    "Qui Est En Ligne" - Fonctionnalité affichant en temps réel les utilisateurs connectés à l'application.
    Quiz Technique
    Questionnaire à choix multiples permettant d'évaluer les compétences techniques d'un candidat. Les réponses sont sauvegardées automatiquement. Peut être associé à un mode anti-triche configurable.
    Source Token
    Code de partage unique généré pour chaque canal de diffusion d'une offre, permettant de tracer l'origine des candidatures (LinkedIn, site web, cabinet, etc.).
    Spécialité
    Domaine de compétence technique (ex: Développement Java, DevOps, Data Science) rattaché à un département et associé à une banque de questions.

    Termes Techniques

    API (Application Programming Interface)
    Interface de programmation permettant à des applications de communiquer entre elles via des requêtes HTTP.
    BCrypt
    Algorithme de hashage sécurisé utilisé pour stocker les mots de passe de manière irréversible.
    CRUD
    Create, Read, Update, Delete - Les quatre opérations de base pour la manipulation des données.
    DTO (Data Transfer Object)
    Objet utilisé pour transférer des données entre les couches de l'application, découplant l'API des entités de base de données.
    JPA (Java Persistence API)
    Spécification Java pour la persistance des données, implémentée par Hibernate dans ce projet.
    MoSCoW
    Méthode de priorisation des exigences : Must have (indispensable), Should have (important), Could have (souhaitable), Won't have (exclu).
    Page Visibility API
    API JavaScript standard du navigateur permettant de détecter quand l'utilisateur quitte l'onglet actif. Utilisée dans le mode anti-triche pour journaliser les changements d'onglet.
    RBAC (Role-Based Access Control)
    Modèle de contrôle d'accès basé sur les rôles, utilisé pour définir les permissions des utilisateurs.
    REST (Representational State Transfer)
    Style d'architecture pour les services web utilisant les méthodes HTTP (GET, POST, PUT, DELETE).
    RGPD
    Règlement Général sur la Protection des Données - Réglementation européenne sur la protection des données personnelles.
    SPA (Single Page Application)
    Application web monopage qui charge dynamiquement le contenu sans rechargement complet de la page.
    WebSocket
    Protocole de communication bidirectionnelle persistante, utilisé pour les fonctionnalités temps réel (QEEL, évaluations collaboratives).
