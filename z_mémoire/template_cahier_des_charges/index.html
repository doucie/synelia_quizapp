    Introduction

    Ce document constitue le Cahier des Charges Fonctionnel de l'application SyneliaQuizApp, une solution web dédiée à la gestion du processus de recrutement avec évaluation technique automatisée.

    Il a pour objectif de formaliser les besoins exprimés par l'entreprise SYNELIA et de définir les spécifications fonctionnelles et techniques de la solution à développer.

    Objectif du document
    Ce cahier des charges sert de référence commune entre les parties prenantes du projet. Il définit le périmètre, les fonctionnalités attendues et les contraintes à respecter.

    Structure du document

    Le présent document est organisé comme suit :

    • Partie I : Présentation générale du projet (contexte, objectifs, périmètre)
    • Partie II : Identification des acteurs et cas d'utilisation
    • Partie III : Spécifications fonctionnelles et techniques détaillées
    • Partie IV : Annexes (glossaire, références)
    I

    Présentation Générale

    Cette partie présente le contexte du projet, les objectifs poursuivis et le périmètre fonctionnel de l'application.

    1 Contexte du Projet

    1.1 Présentation de l'entreprise

    SYNELIA est une entreprise spécialisée dans le développement de solutions numériques et l'accompagnement des organisations dans leur transformation digitale.

    [Compléter avec la présentation détaillée de l'entreprise]

    1.2 Problématique

    Dans le cadre de sa croissance, SYNELIA fait face à des défis récurrents en matière de recrutement de talents techniques :

    • Volume croissant de candidatures à traiter
    • Difficulté d'évaluer objectivement les compétences techniques
    • Temps considérable consacré aux entretiens préliminaires
    • Absence d'outil centralisé pour le suivi du recrutement
    • Coordination difficile entre plusieurs recruteurs

    1.3 Solution proposée

    Face à ces constats, le projet SyneliaQuizApp vise à développer une application web complète permettant de :

    Centraliser la gestion des campagnes de recrutement
    Automatiser l'évaluation technique via des quiz
    Faciliter la collaboration entre recruteurs
    Améliorer l'expérience candidat

    2 Objectifs du Projet

    2.1 Objectifs généraux

    Objectif Description
    Digitalisation Transformer le processus de recrutement manuel en workflow numérique intégré
    Automatisation Automatiser l'évaluation technique des candidats via des quiz
    Collaboration Permettre aux recruteurs de travailler ensemble sur les mêmes campagnes
    Traçabilité Conserver un historique complet de chaque candidature

    2.2 Objectifs spécifiques

    • MUST Développer une application web moderne et responsive
    • MUST Implémenter un système d'authentification sécurisé avec gestion des rôles
    • MUST Créer un module de gestion des campagnes de recrutement
    • MUST Concevoir une interface de passage de quiz avec chronomètre
    • SHOULD Développer un module de planification des entretiens
    • SHOULD Implémenter une interface d'évaluation collaborative
    • COULD Créer un système de notifications en temps réel

    3 Périmètre Fonctionnel

    3.1 Fonctionnalités incluses (In Scope)

    Module Fonctionnalités
    Authentification Connexion, inscription, récupération mot de passe, gestion des rôles
    Référentiels Gestion des départements, spécialités, questions, réponses
    Campagnes Création, configuration, tokens de partage, statistiques
    Candidatures Formulaire, upload CV, vérification email, suivi
    Quiz Passage, chronomètre, calcul de score automatique
    Entretiens Planification, convocations, gestion des statuts
    Évaluations Notation collaborative, commentaires, temps réel
    Décisions Pré-sélection, décision finale, notifications

    3.2 Fonctionnalités exclues (Out of Scope)

    Non inclus dans cette version :
    • Intégration avec des calendriers externes (Google, Outlook)
    • Visioconférence intégrée
    • Matching IA des CV
    • Application mobile native
    • Support multi-langue

    5.2 Parcours Candidat

    Le parcours candidat comprend les étapes suivantes :

    1. Découverte de l'offre via un lien de partage (SourceToken)
    2. Soumission du formulaire de candidature avec CV
    3. Réception de l'email de vérification
    4. Passage du quiz technique
    5. Suivi de l'avancement via le code de suivi

    5.3 Parcours Recruteur

    Le recruteur suit ce workflow :

    1. Création d'une campagne de recrutement
    2. Configuration des questions du quiz
    3. Génération des tokens de partage
    4. Réception et tri des candidatures
    5. Planification des entretiens
    6. Évaluation collaborative
    7. Prise de décision finale

    Spécifications Fonctionnelles

    Cette partie détaille les exigences fonctionnelles et techniques de l'application.

    6 Exigences Fonctionnelles

    6.1 Module Authentification

    ID Exigence Priorité
    AUTH-01 L'utilisateur doit pouvoir se connecter avec email et mot de passe MUST
    AUTH-02 Les mots de passe doivent être hashés avec BCrypt MUST
    AUTH-03 L'utilisateur doit pouvoir réinitialiser son mot de passe par email SHOULD
    AUTH-04 Le système doit gérer trois rôles : super, admin, recruiter MUST

    6.2 Module Quiz

    ID Exigence Priorité
    QUIZ-01 Le quiz doit afficher les questions une par une MUST
    QUIZ-02 Le système doit sauvegarder les réponses en temps réel MUST
    QUIZ-03 Un chronomètre doit s'afficher si le quiz est chronométré SHOULD
    QUIZ-04 Le score doit être calculé automatiquement à la fin MUST
    QUIZ-05 Le candidat doit pouvoir naviguer entre les questions SHOULD

    Glossaire

    API
    Application Programming Interface - Interface de programmation applicative permettant à des applications de communiquer entre elles.
    Campagne
    Offre de recrutement pour un poste spécifique, avec ses propres paramètres de quiz et de sélection.
    CRUD
    Create, Read, Update, Delete - Les quatre opérations de base pour la gestion des données.
    DTO
    Data Transfer Object - Objet utilisé pour transférer des données entre les couches de l'application.
    MoSCoW
    Méthode de priorisation : Must have, Should have, Could have, Won't have.
    REST
    Representational State Transfer - Style d'architecture pour les services web.
    SPA
    Single Page Application - Application web monopage qui charge dynamiquement le contenu.
    Source Token
    Code de partage unique permettant de tracker l'origine des candidatures.
    WebSocket
    Protocole de communication bidirectionnelle en temps réel.
